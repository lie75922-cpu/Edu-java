# V0.4 Rule Mastery、可解释推荐与 Published-Graph 学习路径实现记录

## 1. 交付边界

本阶段在 V0.2 的答题事实和 V0.3 的版本化 Published Graph 之上，实现以下闭环：

```text
AnswerRecord
  -> MASTERY_UPDATE_REQUEST
  -> RuleBasedMasteryProvider
  -> student_knowledge_mastery
  -> weak KnowledgePoint
  -> active Published Graph
  -> Recommendation snapshot
  -> Learning Path
  -> structured explanation
```

`MasteryProvider` 是业务层唯一的掌握度抽象。默认实现为 `RuleBasedMasteryProvider`，版本为 `RULE_BETA_1_1_V1`，使用透明的 Beta(1,1) 平滑：

```text
mastery = (correct_count + 1) / (attempt_count + 2)
```

它是可解释的规则兜底，不是 AI 认知诊断。本阶段没有接入 MODEL-0R、NCDM、ORCDF、ICDM、LLM、Agent、Kafka 或微服务；也不会自动修改 Published Graph。

## 2. V004 Schema

`backend/src/main/resources/db/migration/V004__rule_mastery_recommendation_and_learning_path.sql` 是唯一新增 migration；V001、V002、V003 未修改。

- `student_knowledge_mastery`：学生×知识点当前态，保存答题/正确次数、可空观测掌握度、`RULE` 来源、算法版本、最近答题时间和乐观锁版本。`(student_id, knowledge_point_id)` 唯一。
- `mastery_processed_answer`：以 `answer_record_id` 为主键的消费声明，保证同一答题事实只会更新一次。
- `student_knowledge_mastery_history`：逐知识点保存同一 AnswerRecord 前后的次数、分数、算法版本；`(answer_record_id, knowledge_point_id)` 唯一。
- `recommendation_snapshot`：保存学生、课程、active `graph_version_id`、mastery 算法版本、推荐规则版本、生成时间。
- `recommendation_item`：保存 snapshot 内的稳定 rank、KnowledgePoint、可空 ExerciseUnit、掌握度、ReasonCode 和结构化 explanation JSON。

MySQL 是 mastery 和 recommendation 审计事实源。没有答题历史的知识点不会写入一个伪造的 0.5，而是在读模型/API/前端中返回 `UNKNOWN` 和空 mastery score。

## 3. Mastery Worker 与幂等语义

`MasteryUpdateWorker` 只按 `MASTERY_UPDATE_REQUEST` + `PENDING` 取 Outbox 事件；它不查询也不消费 `GRAPH_REBUILD_REQUEST`。每个事件执行：

1. 读取真实 `AnswerRecord` 与其 ExerciseUnit；
2. 验证 ExerciseUnit 课程一致性以及全部 ExerciseUnit→KnowledgePoint 映射；
3. 无映射、缺失知识点、inactive KnowledgePoint、跨课程映射都标记该 Outbox 为 `FAILED` 并保留明确失败原因；不制造 mastery；
4. 通过 `mastery_processed_answer` 的主键声明原子抢占 `answerRecordId`；重放者只会把自己的 Outbox 标记为 `DONE`；
5. 对每一个有效 KnowledgePoint 映射独立锁定并更新当前态、写 history，再标记 Outbox `DONE`。

因此同一 AnswerRecord 传递 100 次，`attempt_count` 仍只增加一次；一个 ExerciseUnit 映射多个 KnowledgePoint 时，每个 KnowledgePoint 各自拥有一次 history 和独立统计。第 1 次正确写入 `0.6667`，第 1 次错误写入 `0.3333`。

## 4. 推荐与学习路径

推荐管线是四个独立组件，而非巨型 Service：

```text
RecommendationCandidateGenerator
  -> RecommendationFilter
  -> RecommendationRanker
  -> RecommendationExplanationBuilder
```

规则版本为 `REC_RULE_V1`。候选来自已观测且低于 `0.70` 的 ACTIVE KnowledgePoint，以及当前 active Published Graph 中这些弱点尚未掌握的直接 prerequisite；Filter 仅保留同课程、同 active graphVersion、ACTIVE KnowledgePoint、ACTIVE ExerciseUnit 和至少一个 ACTIVE Question 的组合。

排序稳定且不针对学生身份或 fixture 特判：未掌握 prerequisite 优先，然后 mastery 升序、最近错误数降序、距上次练习更久优先，最后按 KnowledgePoint/ExerciseUnit 业务 ID 打破平局。每个 item 的 JSON 明确保存 graphVersion、mastery 状态/次数/分数、前置关系、最近错误数、rank 和稳定 tie-break；ReasonCode 包含 `UNMET_PREREQUISITE`、`LOW_MASTERY`、`RECENT_ERRORS`、`REVIEW_DUE`、`TARGET_PRACTICE`。

学习路径直接调用 V0.3 `PublishedGraphStore.prerequisiteSubgraph(activeGraphVersionId, targetId)`，不在 Java 中维护第二套先修图：

```text
target prerequisite subgraph
  -> remove mastery >= 0.70 nodes
  -> deterministic DAG topological order
  -> unmastered target last
  -> attach first stable ACTIVE ExerciseUnit with ACTIVE Question
```

没有 Published Graph、目标不在当前投影、Neo4j 不可用或子图不是 DAG 都返回明确业务冲突，而不是伪造路径。新图只有完成 V0.3 投影和验证后才会切换 active 指针，因此 V2 投影失败时 recommendation/path 继续绑定 V1。

## 5. API

学生专用 mastery API：

- `GET /api/v1/courses/{courseId}/mastery`
- `GET /api/v1/knowledge-points/{knowledgePointId}/mastery`
- `GET /api/v1/courses/{courseId}/mastery/history`

学生专用推荐和路径 API：

- `POST /api/v1/courses/{courseId}/recommendations`：生成并持久化一个新 snapshot。
- `GET /api/v1/courses/{courseId}/recommendations/latest`
- `GET /api/v1/knowledge-points/{targetKnowledgePointId}/learning-path`

三组 API 均要求 `STUDENT` 且复用课程范围访问检查。V0.3 的 GraphVersion、Evidence、审核、验证、发布、失败原因和 current active version 管理 API/前端继续可用，未扩大教师大屏范围。

## 6. 前端

学生端新增“我的学习”页面，提供：

- 当前规则掌握列表，并把 `UNKNOWN（尚无答题历史）` 与观测 mastery 明确区分；
- 薄弱知识列表；
- 生成/查看审计 recommendation snapshot、绑定的 GraphVersion 和结构化推荐原因；
- 目标 KnowledgePoint 的学习路径及每一步可用 ExerciseUnit；
- mastery 变化 history。

既有 Published Graph 页面继续显示当前图版本、搜索、前驱/后继和两点路径。管理页继续显示 GraphVersion、Evidence、候选审核、validation 问题、发布操作、投影失败原因与 active 标记。

## 8. Bad Cases 与限制

- `UNKNOWN` 不会被 UI 显示为 0.5；它没有答题统计，也不会被当成已诊断 mastery。
- 无映射、inactive、cross-course、缺失 AnswerRecord/ExerciseUnit 都保留 Answer/Outbox 审计并明确失败，不生成伪 mastery。
- 重放和并发的幂等键是 `answerRecordId`，不是请求次数或 Neo4j 内部 ID。
- inactive KnowledgePoint/ExerciseUnit、无 ACTIVE Question、课程外数据和 graphVersion 不匹配候选都会在推荐 Filter 被移除。
- 图不可用或没有 Published Graph 时失败清晰，不回落到 Java 自建边集；投影失败不删除旧图、不提前切换 active 版本。
- 规则 mastery 只表示透明平滑正确率；它不声称衡量深层认知能力，也不替代未来经独立审批的模型。
