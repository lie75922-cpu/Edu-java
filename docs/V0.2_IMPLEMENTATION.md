# V0.2 核心学习闭环实现与验收记录

## 1. 交付边界

本次实现严格止于 V0.2 平台业务闭环：

```text
注册 / 登录
  → Course
  → KnowledgeArea / KnowledgePoint
  → ExerciseUnit
  → platform-owned Question
  → 答题
  → AnswerRecord + MASTERY_UPDATE_REQUEST Outbox
```

它遵守 `ADR-0001`、`ADR-0002` 和 `ADR-0003`：

- `ExerciseUnit`、`KnowledgePoint`、`Question` 是三个独立实体；
- Topic 只能以 `source_type=JUNYI_TOPIC` 进入第一版 KnowledgePoint，不被描述为已人工认证的标准体系；
- 平台 Question 仅由管理员建立，不从 Junyi Exercise 伪造题干、选项、答案或解析；
- Junyi Research Student、ProblemLog、原始 prerequisite、annotation score 和 RCD 图均没有进入平台用户、答题记录或正式图；
- 本交付没有实现 Neo4j Published Graph、推荐、学习路径、模型接入、LLM 或 Agent。

## 2. Schema / ER 摘要

`backend/src/main/resources/db/migration/V002__v0_2_core_business_loop.sql` 是唯一的 V0.2 业务 Schema 迁移；Hibernate 仍保持 `ddl-auto=validate`。

```text
sys_user ──< course_enrollment >── course
                                  ├──< knowledge_area
                                  ├──< knowledge_point
                                  └──< exercise_unit ──< question ──< question_option
                                           │
                                           └──< exercise_knowledge >── knowledge_point

sys_user ──< answer_record >── question / exercise_unit / course
answer_record ── transactional write ──> outbox_event

seed_import_run ──< seed_import_conflict
```

所有主键均为内部 surrogate ID。`external_id` 只被索引，未被设为业务主键或全局唯一键。`answer_record` 保留 `UNIQUE(student_id, client_request_id)`，因此同一学生的重复客户端请求只会形成一条答题事实。

## 4. 答题事务与异常行为

答案提交服务的边界为单个 Spring `@Transactional` 用例：

```text
idempotency check
→ load and authorize active Question / ExerciseUnit / Course
→ server-side judge
→ persist AnswerRecord
→ persist MASTERY_UPDATE_REQUEST to outbox_event
→ commit
```

SINGLE_CHOICE、MULTIPLE_CHOICE、TRUE_FALSE 都由服务端依据存储的答案选项判定。重放相同 `clientRequestId` 会返回原结果而不再次写 AnswerRecord 或 Outbox。

关键拒绝路径包括：不存在或禁用 Question、禁用 ExerciseUnit、未入课学生、重复选项、选项不属于题目、无效题型或无效管理员请求。真实 MySQL 集成测试还覆盖了数据库长度错误时整个答题事务回滚且没有 AnswerRecord / Outbox 残留。

## 5. 受控 Junyi catalog seed 规则

请求 DTO 只包含 Course、Area、Topic、Exercise 元数据，不存在任何研究用户或行为日志字段。

允许：

- Area → KnowledgeArea；
- Topic → KnowledgePoint，且固定来源 `JUNYI_TOPIC`；
- 身份唯一的 Exercise → ExerciseUnit；
- Exercise → Topic 的可审计映射。

禁止：

- Research Student → `sys_user`；
- ProblemLog → `answer_record`；
- raw prerequisite / annotation / RCD relation → Published Graph；
- 自动合并重复 `external_id`。

Importer 提供 dry-run 和 apply；两者都留下 import run / conflict 审计。输入或现存目录中一个 source external ID 对应多个候选时，项目写入 `DUPLICATE_SOURCE_EXTERNAL_ID` 或 `IDENTITY_CONFLICT`，该条目不会被导入或合并。缺少/无法解析 Topic 的 Exercise 保持 `UNMAPPED` 并进入冲突报告。重复应用相同、无冲突的 catalog 不会复制已存在的 Area、KnowledgePoint、ExerciseUnit 或映射。

## 6. 前端最小操作路径

`frontend/src/App.vue` 通过 Vite proxy 调用 `/api`：

1. 注册或登录；
2. 加入课程并查看 KnowledgePoint / ExerciseUnit；
3. 取下一道平台题、选择答案、查看判题结果和解析；
4. 查看个人答题历史；
5. 教师/系统管理员维护 Course、Area、KnowledgePoint、ExerciseUnit、题目和映射；
6. 系统管理员执行 seed dry-run/apply 并查看冲突结果。

## 7. 本地启动

1. 复制 `.env.example` 到本地 `.env`，填入私有 `JWT_SECRET`，并在需要管理入口时设置成对的 bootstrap admin 变量。
2. 启动基础设施：`docker compose up -d mysql redis neo4j`。
3. 后端：在 `backend/` 运行 `mvn spring-boot:run`，或使用本机 Maven 的等价命令。Flyway 会执行 V001 与 V002；不会生成 Hibernate DDL。
4. 前端：在 `frontend/` 运行 `npm install --no-audit --no-fund`，然后 `npm run dev`。

生产前必须替换所有 `.env.example` 占位值；该示例文件不含可用凭据。
