# 当前V0.7与申报书的产品差距

| 维度 | 申报书目标 | 当前V0.7 | 结论 |
| --- | --- | --- | --- |
| 课程定位 | 《离散数学》教学优化平台 | Junyi研究数据 + 少量Demo课程 | 严重偏离 |
| 语言 | 面向教师/学生的教学产品 | 大量英文/研发术语 | 不合格 |
| 知识体系 | 章→节→知识集→知识点，覆盖集合论、数理逻辑、图论、代数结构等 | 业务层级更偏通用Course/Area/Point/Exercise | 需要产品适配 |
| 知识图谱 | 学生核心学习入口，可视化、检索、节点资源、层次/关系 | 有图数据能力，但产品呈现偏工程Demo | 需要重做UI |
| 教学资源 | 视频、动画、文档、案例、练习、课件、测试、代码/虚拟实验 | 资源中心未形成 | 关键缺口 |
| 个性化推荐 | 学习进度、薄弱点、动态路径、资源推荐、路径可视化 | 有RuleBeta/推荐/路径算法，但展示和资源层不足 | 算法底座可复用，产品层重做 |
| 教学评估 | 过程性、诊断性、结果性评价，教师/学生双视角 | 有Teacher Analytics，但没有申报书式评价产品结构 | 需要重构 |
| 教师工作台 | 备课、资源、教学进度、学情、评价 | 主要是analytics | 功能组织不足 |
| 管理端 | 清晰分模块管理 | 大量管理表单堆叠 | 严重不合格 |
| 视觉 | 教育数字平台，图谱/路径/资源/评价可视化 | 工程控制台感强 | 严重不合格 |
| Demo数据 | 应体现离散数学知识与教学资源 | 仅2门小型合成课程 | 明显不足 |
| 工程可靠性 | 作为技术保障 | V0.7已很强 | 保留 |

结论：V0.7只能被视为“工程底座Release Candidate”，不能被视为“申报书产品已完成”。V1必须以产品层重构为核心，不再继续用工程验收代替教学产品验收。
