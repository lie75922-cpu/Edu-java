# V0.1 工程骨架设计

## 1. 目标

V0.1 不实现完整业务功能，目标是建立后续所有版本依赖的工程底座，并验证以下事实：

1. Java 21 + Spring Boot 能稳定启动；
2. MySQL、Redis、Neo4j 三种基础设施连接方式确定；
3. Flyway 数据库迁移可重复执行；
4. 模块化单体目录确定；
5. Python FastAPI 模型服务具备独立健康检查；
6. Vue 前端可以独立启动；
7. Docker Compose 可以一次启动本地基础设施；
8. 研发数据管线与在线业务系统在仓库层面物理分离；
9. 后续 V0.2～V1.0 无需推翻目录和依赖关系。

---

## 2. 技术选型

### Java

- Java 21 LTS
- Spring Boot 4.1.x
- Maven

### Spring 官方组件

- Spring Web MVC
- Spring Validation
- Spring Security
- Spring Data JPA
- Spring Data Redis
- Spring Data Neo4j
- Spring Boot Actuator
- Flyway

V0.1 不引入 MyBatis-Plus。原因：工程骨架优先使用 Spring Boot 官方依赖管理，降低 Spring Boot 4.x 初期第三方兼容性风险。Repository 具体实现以后仍可替换，不影响领域接口。

### 数据库

- MySQL 8
- Redis 7
- Neo4j（开发环境使用兼容 Java 21 的当前版本）

### Python

- Python 3.10+
- FastAPI
- Uvicorn

V0.1 不安装 PyTorch/DGL；模型依赖在 MODEL-0 阶段加入，避免基础服务镜像过大。

### 前端

- Vue 3
- Vite

V0.1 只建立可启动页面和 API 健康状态占位，不做完整UI。

## 4. 模块依赖约束

Java 模块按业务能力组织，而不是全项目横向的 controller/service/mapper。

推荐依赖方向：

```text
api → application → domain
             ↓
       infrastructure
```

约束：

1. `domain` 不依赖 Spring Web、数据库实体或 HTTP DTO；
2. `application` 负责编排用例；
3. `infrastructure` 实现数据库、Redis、Neo4j、HTTP Client；
4. Controller 不直接调用 Repository；
5. 不允许 `recommendation` 直接访问模型实现细节，只调用 `model` 模块定义的 Gateway；
6. 不允许 Neo4j 成为业务事实的唯一存储。

V0.1 只建立模块目录和少量公共类，不制造大量空类。

## 5. V0.1 数据库范围

V0.1 只创建最小基础表，避免在 DATA-0 完成前过早冻结全部业务 Schema。

### sys_user

```text
id BIGINT PK
username VARCHAR(64) UNIQUE
password_hash VARCHAR(255)
nickname VARCHAR(64)
status VARCHAR(20)
created_at DATETIME(3)
updated_at DATETIME(3)
```

### sys_role

```text
id BIGINT PK
role_code VARCHAR(32) UNIQUE
role_name VARCHAR(64)
```

### sys_user_role

```text
user_id BIGINT
role_id BIGINT
UNIQUE(user_id, role_id)
```

### outbox_event

先建立可靠异步机制的表结构占位，后续答题、图谱发布和模型刷新都复用该机制。

```text
id BIGINT PK
event_type VARCHAR(64)
aggregate_type VARCHAR(64)
aggregate_id VARCHAR(128)
payload_json JSON
status VARCHAR(20)
retry_count INT
next_retry_at DATETIME(3)
created_at DATETIME(3)
processed_at DATETIME(3)
last_error TEXT
version BIGINT
```

其余 Course/Exercise/Knowledge/Question 表在 DATA-0 与 V0.2 设计复核后再迁移。

## 6. 配置设计

所有密码和地址使用环境变量。

示例：

```text
MYSQL_DATABASE=edu
MYSQL_USER=edu
MYSQL_PASSWORD=...
MYSQL_ROOT_PASSWORD=...
REDIS_HOST=localhost
NEO4J_URI=bolt://localhost:7687
NEO4J_USERNAME=neo4j
NEO4J_PASSWORD=...
MODEL_SERVICE_BASE_URL=http://localhost:8001
```

禁止把真实密码提交到 GitHub。

## 7. Spring Boot V0.1 能力

### 必须实现

- 应用启动；
- `/api/v1/system/health`；
- Actuator `/actuator/health`；
- 全局统一响应对象；
- 基础异常处理；
- Security 默认策略；
- Flyway迁移；
- MySQL/Redis/Neo4j配置占位；
- 测试上下文可以在 `test` profile 下绕开外部基础设施或使用Mock配置。

### 暂不实现

- JWT完整签发；
- 注册/登录业务；
- Course CRUD；
- 图谱导入；
- 模型推理；
- 推荐逻辑。

这样可以避免把V0.1做成半成品大杂烩。

## 8. Security V0.1 设计

V0.1 允许：

- `/api/v1/system/health`
- `/actuator/health`

其余接口默认要求认证。

但V0.1不实现JWT Filter，只保留后续接入点。

测试阶段可通过 `test` profile 放宽安全限制。

## 9. Docker Compose

V0.1 Compose 只负责基础设施：

- MySQL
- Redis
- Neo4j

应用本身优先本地运行，便于调试。

后续 `demo` profile 再把：

- backend
- frontend
- model-service

加入完整Compose。

这种做法比开发期每次都重新build全部应用容器更高效。
