# V1 产品层重构说明

## 背景

V0.7 已完成可靠的 Java/数据/图谱/部署底座，但当前前台产品形态被 Owner 否决：中文化不彻底、界面信息架构混乱、课程内容仅为少量 Demo、管理功能堆叠、整体观感偏工程后台，与原《基于〈离散数学〉数字教材的知识图谱建设与应用》申报书不一致。

因此后续不是继续加新后端模块，而是：**保留工程底座，重做产品层。**

## 申报书对齐目标

最终产品以《离散数学》为核心课程，围绕四大模块组织：

1. 知识图谱可视化；
2. 教学资源整合与管理；
3. 个性化学习推荐；
4. 多元化教学评估。

课程知识体系采用：

```text
离散数学
├─ 数理逻辑
├─ 集合论与关系
├─ 图论
├─ 代数结构
└─ 组合数学/扩展
```

进一步细分：章 → 节 → 知识集 → 知识点。

## 产品原则

- 学生、教师、管理员三套信息架构分离；
- 普通用户界面全部自然中文；
- 不在学生/教师界面暴露 KnowledgePoint、ExerciseUnit、GraphVersion、Evidence、RuleBeta、UNKNOWN 等研发术语；
- 每个知识点可关联教材、课件、视频、动画、案例、练习题、测试题、代码/虚拟实验；
- 知识图谱作为学生学习入口之一，而不是后台数据页；
- 学习路径必须图形化展示已掌握、待学习、薄弱和目标节点；
- 教师端围绕备课、资源、教学进度、班级学情和评价组织；
- 管理端按用户与组织、课程与教学、资源中心、知识图谱、系统设置分栏，不再一页堆叠所有CRUD；
- Junyi 仅保留为算法研究数据，不再作为最终前台课程品牌和主展示内容。

## 学生端目标结构

- 首页：今日学习、课程进度、薄弱知识、推荐任务、近期评价；
- 课程学习：离散数学课程目录、章节进度、知识点详情；
- 知识图谱：可缩放/拖拽/检索/筛选，点击节点打开知识详情与关联资源；
- 学习资源：按视频/课件/文档/案例/练习分类；
- 个性化学习：薄弱知识、推荐理由、学习路径、资源推荐；
- 练习与测验：章节练习、知识点自测、错题与解析；
- 学习报告：学习进度、答题正确率、知识掌握分布、过程性评价与阶段结果。

## 教师端目标结构

- 教师首页：本周教学、班级预警、待批阅/待处理、课程资源概览；
- 课程与教学：教学进度、章节安排、课前/课中/课后任务；
- 资源中心：教材、课件、视频、动画、文档、案例、练习、测试题；
- 知识图谱：课程知识结构、节点资源、关系维护入口；
- 学情分析：班级概览、知识点掌握、学生下钻、错误分布、学习轨迹；
- 教学评价：过程性、诊断性、结果性评价；
- 智能备课：按知识点聚合资源、查看先修/后继知识和班级薄弱点。

## 管理端目标结构

- 工作台；
- 用户与组织；
- 课程与教学；
- 教学资源中心；
- 知识图谱治理；
- 数据与评价；
- 系统设置与审计。

高级图谱治理中的 Evidence / Draft / GraphVersion 保留，但放入“知识图谱治理 > 高级治理”，不直接作为首页主功能。

## 视觉目标

- 中文教育数字平台风格，而非开发者控制台；
- 统一顶部品牌区 + 左侧模块导航 + 面包屑 + 内容工作区；
- 使用清晰的卡片、图表、进度条、知识图谱画布和资源缩略图；
- 页面层级明确，避免一个页面出现十几个无关表单；
- 默认展示真实业务名词，不展示数据库字段名/内部ID；
- 申报书中的知识图谱、个性化路径、教师/学生评估视角作为视觉参考，但不机械复刻老式页面。

## 工程底座保留

以下不推翻：

- Java 21 / Spring Boot / Spring Security / JWT / RBAC；
- MySQL / Neo4j / Redis；
- Flyway；
- AnswerRecord / Outbox / Mastery exactly-once；
- Evidence → Draft → Validator → Published Graph；
- RuleBeta Mastery；
- Recommendation / Learning Path；
- Teacher course authorization / analytics；
- Docker / OpenAPI / Playwright / backup-restore。

重构重点是课程领域数据、资源模型补全、中文产品语言、导航与页面拆分、图谱与学习路径视觉交互。
