# V1 产品重构验收标准

## 总体Gate

V1产品层必须同时满足以下条件才允许进入“最终展示/简历固化”：

### 1. 中文化
- 学生端、教师端、管理员端可见业务文案100%自然中文；
- 不直接展示KnowledgePoint、ExerciseUnit、GraphVersion、Evidence、RuleBeta、UNKNOWN等研发术语；
- 内部ID仅在高级治理/运维场景出现。

### 2. 离散数学课程对齐
- 前台主课程为《离散数学》；
- 至少覆盖数理逻辑、集合论与关系、图论、代数结构四大核心分支；
- 课程层次至少支持章、节、知识集、知识点；
- 不得用Junyi基础数学Demo冒充最终课程内容。

### 3. 四大模块
必须明确独立呈现：
1. 知识图谱可视化；
2. 教学资源整合与管理；
3. 个性化学习推荐；
4. 多元化教学评估。

### 4. 学生端体验
- 首页不是后台列表；
- 有课程进度、学习任务、薄弱知识、推荐路径；
- 知识图谱可交互；
- 知识点详情可查看定义/关系/资源/练习；
- 学习路径图形化，区分已掌握、待学习、薄弱、目标；
- 有错题、测验和学习报告。

### 5. 教师端体验
- 独立教师导航；
- 资源管理与智能备课入口；
- 班级学情、学生下钻、错误分布、知识点掌握；
- 过程性/诊断性/结果性评价分开；
- 不把GraphVersion/Evidence等工程概念作为教师首页主内容。

### 6. 管理端体验
- 按“用户与组织 / 课程与教学 / 教学资源 / 知识图谱 / 数据与评价 / 系统设置”拆分；
- 禁止所有管理功能堆在一个长页面；
- 高级图谱治理收进二级页面。

### 7. 视觉
- 统一中文教育平台视觉；
- 侧边导航、顶部状态栏、面包屑、卡片、图表、资源缩略图、图谱画布样式统一；
- 页面必须有清晰视觉层级；
- 禁止直接使用开发者表单和JSON文本框作为普通用户主交互。

### 8. 工程回归
- V0.7已有后端可靠性、权限、图谱治理、推荐/路径、Docker、E2E必须保持；
- 重构不能破坏Teacher A→Course B 403、Mastery exactly-once、Published Graph失败回退等关键不变量；
- 新UI必须补角色级Playwright E2E。

## 不在V1首轮强制范围
- LLM/Agent；
- 新推荐算法；
- 新CD/GNN模型；
- 微服务/Kafka/Kubernetes；
- 云厂商部署。

V1首轮目标是把已有强工程底座变成一个与申报书一致、能真正展示的《离散数学》教学优化产品。
