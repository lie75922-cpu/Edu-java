# V0.6 Authorization Matrix

本文件补充 `ADR-0009` 与 `V0.6_SCOPE_AND_ACCEPTANCE.md`，用于防止“角色注解存在，但 Course 级资源归属未校验”的越权。

## 1. 角色语义

| 操作 | SYSTEM_ADMIN | TEACH_ADMIN | TEACHER | STUDENT |
| --- | --- | --- | --- | --- |
| 创建/修改/停用 Course | allow | allow | deny | deny |
| 管理 Teacher-Course assignment | allow | allow | deny | deny |
| 查看所有 Course | allow | allow | assigned only | enrolled only |
| 管理 Knowledge/Exercise/Question | allow all | allow all | assigned only | deny |
| Graph/Evidence governance | allow all | allow all | assigned only | deny |
| Teacher analytics | allow all | allow all | assigned only | deny |
| Student learning API | admin as designed | admin as designed | teaching read only | own enrolled courses |

普通 TEACHER 的 `assignment_role=OWNER/INSTRUCTOR` 在 V0.6 均要求 ACTIVE assignment；不借此重新设计复杂课程所有权。

## 2. 现有 Controller 回归范围

代码审查已确认下列旧入口以粗粒度 `SYSTEM_ADMIN | TEACHER` 为主，V0.6 必须逐个检查并改为“角色 + course resource authorization”。

### AdminCourseController

- `POST /api/v1/admin/courses`
- `PUT /api/v1/admin/courses/{courseId}`
- `DELETE /api/v1/admin/courses/{courseId}`

V0.6：仅 SYSTEM_ADMIN / TEACH_ADMIN。

### AdminKnowledgeController

所有创建/修改/删除 KnowledgeArea / KnowledgePoint 的入口：

- SYSTEM_ADMIN / TEACH_ADMIN：全部课程；
- TEACHER：先从 request/path entity 解析 courseId，再检查 ACTIVE assignment；
- 若 update request 携带 courseId，不得通过修改字段把 entity 从已授权 Course 移到未授权 Course；源 Course 和目标 Course 都必须符合权限/领域约束。

### AdminExerciseUnitController

ExerciseUnit 与 Exercise-Knowledge mapping：

```text
exerciseUnitId -> courseId -> authorization
knowledgePointId -> courseId -> same-course validation
```

TEACHER 不得把已授权课程 Exercise 映射到别的 Course KnowledgePoint。

### AdminQuestionController

```text
questionId -> ExerciseUnit -> courseId -> authorization
```

create 也必须从目标 ExerciseUnit 解析 courseId，不能让 TEACHER 通过猜 ExerciseUnit ID 写入别的课程。

### AdminGraphController

```text
graphVersionId -> courseId -> authorization
evidenceId -> courseId -> authorization
relationId -> graphVersionId -> courseId -> authorization
importRunId -> graphVersion/course -> authorization
```

需要覆盖：

- version create/list/get；
- relation create/review/reject；
- Evidence import/list/history；
- re-resolution dry-run/apply；
- validation/publish/retry；
- conflict查询。

## 3. Service 层要求

Course 级授权不得只放 Controller。

推荐统一组件：

```text
CourseAuthorizationService
```

至少：

```text
requireRead(courseId, CurrentUser)
requireTeaching(courseId, CurrentUser)
requirePlatformTeachingAdmin(CurrentUser)
```

或者在现有 `CourseAccessService` 中重构出等价方法。

资源 Service 在执行写操作之前调用授权；Controller 的 `@PreAuthorize` 仅做角色粗筛。

对于没有 `CurrentUser` 参数的现有 service，可：

1. 在 Controller 解析资源 Course 并调用统一 authorization service；且
2. 对关键写 service 新增安全入口/参数，避免未来内部调用绕开；

最终方案必须在实现报告中说明安全边界。

## 4. 必须真实测试的越权矩阵

Fixture：

```text
Teacher-A -> Course-A ACTIVE
Teacher-B -> Course-B ACTIVE
Student-A -> Course-A ACTIVE
Student-B -> Course-B ACTIVE
```

### Teacher-A 应允许

- read Course-A teaching content；
- manage Course-A Knowledge/Exercise/Question；
- govern Course-A Draft/Graph；
- view Course-A analytics / Student-A detail。

### Teacher-A 必须拒绝

- Course-B analytics；
- Student-B detail；
- Course-B Knowledge update；
- Course-B Exercise mapping；
- Course-B Question create/update；
- Course-B GraphVersion relation review/publish；
- Course-B Evidence re-resolution；
- Course-B import conflict/history query；
- create/update/disable platform Course；
- create own Teacher-Course assignment。

### Assignment 状态

Teacher-A assignment 改为 INACTIVE 后，上述 Course-A teacher actions 全部拒绝。

### Admin

SYSTEM_ADMIN / TEACH_ADMIN 对合法数据均允许，并可管理 assignment。

### Student

Student-A：

- 自己的 Course-A 学习接口保持可用；
- 所有 `/teacher/**` 与管理写接口拒绝；
- 不能查询 Student-B。

## 5. HTTP 语义

- authenticated but unauthorized course resource → `403`；
- resource truly不存在 → `404`；
- 对需要防资源枚举的接口可以采用统一安全策略，但同类接口必须一致并在文档中说明；
- 不应返回 SQL、内部堆栈、密码/JWT 等敏感信息。

## 6. 验收要求

V0.6 不能仅因为新 teacher analytics endpoint 的权限测试通过就过 Gate。

必须同时证明：

> V0.2–V0.5 已存在的教师可写入口不再存在跨 Course 越权。

否则 Final Gate 至少为 `CONDITIONAL_GO`，严重越权则 `NO_GO`。
