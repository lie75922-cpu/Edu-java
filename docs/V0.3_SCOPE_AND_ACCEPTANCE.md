# V0.3：知识关系证据治理与Published Graph范围/验收标准

## 1. 阶段目标

V0.3把V0.2已经存在的：

```text
Course
KnowledgePoint
ExerciseUnit
```

扩展为一个**可审核、可版本化、可失败回滚、可由Neo4j高效查询**的正式知识关系系统。

本版本解决的是：

> “哪些KnowledgePoint之间的先修关系可以被平台正式发布，以及如何安全查询这些关系？”

不解决：

> “某学生当前掌握多少？”

也不解决：

> “下一步给学生推荐什么？”

---

# 2. 业务闭环

V0.3必须打通：

```text
关系Evidence导入/录入
   ↓
Evidence身份解析
   ↓
KnowledgePoint Candidate关系
   ↓
管理员审核/人工关系维护
   ↓
GraphValidator
   ↓
READY Graph Version
   ↓
异步投影Neo4j
   ↓
Published Version切换
   ↓
学生/教师只读图查询
```

---

# 3. 数据库设计要求

使用Flyway新增V003，不修改已经执行的V001/V002。

至少包括以下结构。

## 3.1 `knowledge_relation_evidence`

用途：保存外部/人工关系依据，而不是正式边。

建议字段：

```text
id
course_id
source_type
source_external_id
target_external_id
source_exercise_unit_id
target_exercise_unit_id
source_knowledge_point_id
target_knowledge_point_id
raw_payload_json
resolution_status
created_at
```

`source_type`至少支持：

```text
JUNYI_RAW_PREREQUISITE
ANNOTATION
REFERENCE_GRAPH
MANUAL_EVIDENCE
```

`resolution_status`至少：

```text
RESOLVED
UNRESOLVED_IDENTITY
UNMAPPED_SOURCE
UNMAPPED_TARGET
REJECTED_SELF_LOOP
```

Evidence不得因为无法转成正式边而删除。

## 3.2 `graph_version`

至少：

```text
id
course_id
version_no
status
description
created_by
created_at
validated_at
published_at
failure_reason
```

同Course `version_no`唯一。

## 3.3 `knowledge_relation`

表示某个GraphVersion内的KnowledgePoint关系快照。

至少：

```text
id
graph_version_id
source_knowledge_point_id
target_knowledge_point_id
relation_type
relation_source
confidence
evidence_count
review_status
created_by
created_at
```

`relation_type` V0.3正式只要求：

```text
PREREQUISITE
```

不要为了“看起来丰富”提前加入大量没有业务用处的关系类型。

`review_status`至少：

```text
CANDIDATE
APPROVED
REJECTED
```

版本内：

```text
UNIQUE(graph_version_id, source_knowledge_point_id, target_knowledge_point_id, relation_type)
```

## 3.4 Relation-Evidence link

为正式/候选边和多个Evidence之间建立可追溯关联，例如：

```text
knowledge_relation_evidence_link
```

至少：

```text
relation_id
evidence_id
```

不能只保存 `evidence_count=5` 却无法知道是哪5条Evidence。

## 3.5 Course active version

V003为`course`增加：

```text
active_graph_version_id NULL
```

只能指向本Course成功发布的GraphVersion。

# 4. Evidence Import

## 4.1 Junyi raw prerequisite importer

必须提供：

```text
dry-run
apply
conflict/report
```

输入只接受关系证据以及必要的source metadata，不读取或导入Research Student。

流程：

```text
source Exercise external ID
 target Exercise external ID
       ↓
解析内部ExerciseUnit
       ↓
读取已存在Exercise→KnowledgePoint映射
       ↓
保留Evidence
       ↓
若可唯一映射，生成/聚合KnowledgePoint candidate
```

### 必须处理

- duplicate Exercise external ID；
- source/target不存在；
- Exercise未映射KnowledgePoint；
- source/target映射到同一KnowledgePoint；
- 重复Evidence；
- 重复import。

不得静默自动合并身份冲突。

## 4.2 人工关系

系统管理员应能在Draft版本中手工添加：

```text
KnowledgePoint A -> KnowledgePoint B
```

并记录：

```text
relation_source = MANUAL
created_by
```

人工关系也必须经过GraphValidator，不能绕过DAG约束。

# 5. Draft Version操作

至少支持：

- 从当前Published版本复制新Draft；
- 创建空Draft；
- 查看Draft关系；
- 将candidate批准/拒绝；
- 手工增加关系；
- 删除/拒绝Draft关系；
- 查看每条边的Evidence；
- 运行validate；
- 查看validation问题。

Published版本不可直接编辑。

# 6. GraphValidator

必须有独立领域服务，不把验证逻辑散在Controller。

至少输出结构化Issue：

```text
SELF_LOOP
DUPLICATE_EDGE
CROSS_COURSE_EDGE
MISSING_SOURCE_NODE
MISSING_TARGET_NODE
INACTIVE_NODE
CYCLE
NO_EVIDENCE_WARNING
NO_EXERCISE_COVERAGE_WARNING
```

`ERROR`会阻止READY。

`WARNING`记录但不一定阻止。

### Cycle

必须返回至少：

```text
cycle node IDs
cycle node codes/names
representative directed cycle
```

不允许只返回：

> graph has cycle

导致管理员无法治理。

# 7. Neo4j Projection

V0.3正式投影只包含KnowledgePoint。

节点：

```text
(:KnowledgePoint {
  projectionKey,
  businessId,
  courseId,
  graphVersionId,
  code,
  name
})
```

关系：

```text
[:PREREQUISITE {
  relationId,
  graphVersionId,
  relationSource
}]
```

必须建立并测试`projectionKey`唯一约束。

禁止依赖Neo4j内部node id作为Java业务ID。

# 8. 发布与Outbox

发布采用ADR-0005定义的异步过程。

新增事件：

```text
GRAPH_REBUILD_REQUEST
```

必须确保Graph worker只处理该事件类型，不会消费已有：

```text
MASTERY_UPDATE_REQUEST
```

发布请求本身只：

1. 再校验READY；
2. 标记PUBLISHING；
3. 写Outbox；
4. commit。

Neo4j实际投影在worker执行。

### Worker成功

```text
project
verify
MySQL active pointer switch
new=PUBLISHED
old=ARCHIVED
outbox=DONE
```

### Worker失败

```text
new=PROJECTION_FAILED
old active graph保持不变
outbox按既定策略retry/dead
```

V0.3必须证明：“新图发布失败不会把当前在线图打坏”。

# 9. 查询API

学生/教师访问必须基于Course active graph version。

至少：

```text
GET /api/v1/courses/{courseId}/graph
GET /api/v1/knowledge-points/{id}/prerequisites
GET /api/v1/knowledge-points/{id}/successors
GET /api/v1/courses/{courseId}/graph/path?from={id}&to={id}
GET /api/v1/knowledge-points/{id}/prerequisite-subgraph
```

响应必须携带：

```text
graphVersionId
```

无Published Graph时返回明确业务状态，不假装空图就是有效图。

管理员至少：

```text
POST /api/v1/admin/graph-versions
GET  /api/v1/admin/graph-versions
GET  /api/v1/admin/graph-versions/{id}
POST /api/v1/admin/graph-versions/{id}/validate
POST /api/v1/admin/graph-versions/{id}/publish
POST/DELETE/PUT relation operations
Evidence import dry-run/apply endpoints
```

# 10. 前端最低功能

## 学生/普通用户

新增知识图页面：

- 显示当前Published版本；
- 节点名称；
- prerequisite方向；
- 搜索KnowledgePoint；
- 点击查看前置/后继；
- 两点路径查询。

可以使用轻量图可视化库，但不得牺牲构建稳定性。

## 管理员

需要：

- Graph Version列表/状态；
- Draft关系表；
- Evidence详情；
- candidate approve/reject；
- validation issues；
- publish状态和失败原因；
- 当前active version。

重点是治理可见，不是只画漂亮图。

# 11. 测试要求

## Unit

至少：

- self-loop阻断；
- 2-node cycle；
- 3+ node cycle；
- cross-course；
- duplicate relation；
- unresolved Evidence不发布；
- same-Topic映射成为REJECTED_SELF_LOOP；
- duplicate source ID不猜测合并；
- candidate aggregate retains evidence links。

## MySQL integration

通过MySQL 8.4 Testcontainers验证：

- V003 Flyway；
- Draft/version生命周期；
- active pointer；
- outbox GRAPH_REBUILD_REQUEST事务；
- publish request rollback。

## Neo4j integration

使用真实Neo4j Testcontainer或等价可验证环境：

- 创建约束；
- project一个3+节点DAG；
- prerequisite query；
- successor query；
- path query；
- version隔离；
- projection失败时旧active version仍可查询。

如CI环境无法运行Neo4j integration，应明确区分本地通过与CI跳过，不能冒充。

## Regression

V0.2：

- JWT/RBAC；
- Course/Question/Answer；
- MySQL Answer+Outbox；
- seed importer；

所有现有测试继续通过。

# 13. 禁止范围

V0.3不做：

- MasterySnapshot；
- MODEL-0R结果生产接入；
- Personalized Recommendation；
- Mastery-aware Learning Path；
- LLM；
- Agent；
- Kafka；
- 微服务拆分。

这些只能在新的Gate之后进入。
