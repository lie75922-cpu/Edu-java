# V0.6 Scope & Acceptance — Teacher Authorization + Learning Analytics

## 1. 阶段目标

V0.6 在 V0.5 后增加安全、可审计的教师学情分析能力。

完成后的最小业务闭环：

```text
教学管理员分配 Teacher -> Course
          ↓
Teacher 只能进入已分配 Course
          ↓
查看班级学习概览
          ↓
KnowledgePoint 掌握分布 / 学生热力图
          ↓
高错误 Question
          ↓
下钻单个 Student
          ↓
Answer / Mastery / Recommendation evidence
```

V0.6 不依赖 MODEL-2 结果；所有 mastery 按当前生产 `MasteryProvider` 数据读取，默认仍是 `RULE_BETA_1_1_V1`。

---

- NCDM / ORCDF / RCD / GEAR-CD / ICDM 生产接入；
- 新的认知诊断算法实验；
- LLM / Agent；
- Kafka / Spark / Flink；
- 微服务拆分；
- 数据仓库 / OLAP 引擎；
- 自动预警推送；
- 跨学校/组织 tenant；
- 教师主观评语生成；
- 为展示而生成假班级数据并宣称生产指标。

# 3. WP-V06.1 — Flyway V006

不得修改 V001-V005。

新增：

## `course_teacher_assignment`

最低字段：

```text
id
teacher_id
course_id
assignment_role   OWNER | INSTRUCTOR
status            ACTIVE | INACTIVE
assigned_by
assigned_at
created_at
updated_at
```

约束：

- UNIQUE `(teacher_id, course_id)`；
- FK teacher → sys_user；
- FK course → course；
- FK assigned_by → sys_user（可 ON DELETE SET NULL）；
- 应有 course/status 与 teacher/status 索引。

应用层必须验证被分配用户拥有 TEACHER 教学角色；数据库 FK 本身不能替代角色校验。

## Analytics support indexes

至少评估并按实际 EXPLAIN/测试需要增加：

```text
answer_record(course_id, answered_at, id)
answer_record(course_id, question_id, answered_at)
```

如果现有索引已覆盖或额外索引无收益，可不加，但实现报告必须解释。

# 4. WP-V06.2 — Teacher Assignment 管理

只允许：

- `SYSTEM_ADMIN`
- `TEACH_ADMIN`

管理 Teacher-Course assignment。

建议 API：

```text
GET    /api/v1/admin/courses/{courseId}/teachers
POST   /api/v1/admin/courses/{courseId}/teachers
PUT    /api/v1/admin/courses/{courseId}/teachers/{teacherId}
DELETE /api/v1/admin/courses/{courseId}/teachers/{teacherId}
```

DELETE 可实现为 INACTIVE，优先保留审计事实；如果采用物理删除必须说明理由。

请求至少支持：

```json
{
  "teacherId": 123,
  "assignmentRole": "INSTRUCTOR"
}
```

必须拒绝：

- 不存在用户；
- STUDENT-only 用户；
- 不存在课程；
- 非法 role/status；
- 普通 TEACHER 自己给自己分配任意课程。

# 5. WP-V06.3 — 收紧 Course Authorization

当前 `TEACHER` 角色全课程放行必须移除。

统一访问矩阵：

| 用户 | Course read | Teaching analytics | Graph governance |
| --- | --- | --- | --- |
| SYSTEM_ADMIN | all | all | all |
| TEACH_ADMIN | all | all | all |
| TEACHER | assigned ACTIVE only | assigned ACTIVE only | assigned ACTIVE only |
| STUDENT | enrolled ACTIVE only | no | no |

必须覆盖直接 courseId 和间接资源：

- graphVersionId；
- evidenceId；
- KnowledgePointId；
- StudentId + CourseId；
- recommendation/mastery drill-down。

所有课程级权限必须在服务层或统一授权组件中再次验证，不能只依赖 UI 或 controller 角色注解。

### 必测安全场景

```text
Teacher A assigned Course A
Teacher B assigned Course B
```

Teacher A：

- Course A analytics = 200；
- Course B analytics = 403；
- Course B graphVersion/evidence governance = 403；
- 直接猜 Student B ID = 403。

# 6. WP-V06.4 — Teacher Course List

API：

`GET /api/v1/teacher/courses`

TEACHER 只返回 ACTIVE assignments。

SYSTEM_ADMIN / TEACH_ADMIN 可返回全部可教学课程或提供等价管理入口。

至少返回：

- courseId/code/name/status；
- assignmentRole；
- activeEnrollmentCount；
- latestAnswerAt（可空）。

禁止通过返回全部课程后让前端自己过滤权限。

# 7. WP-V06.5 — Course Overview

API建议：

`GET /api/v1/teacher/courses/{courseId}/analytics/overview?from=...&to=...`

默认：最近30天。
最大：365天。

响应必须返回 resolved window。

至少：

```text
activeEnrolledStudents
studentsWithActivity
attemptCount
correctCount
correctRate
activeKnowledgePointCount
observedMasteryStudents
latestActivityAt
masteryAlgorithmVersions
```

可增加有明确语义的：

- recommendationSnapshotsGenerated；
- weakObservedKnowledgePointCount（明确阈值/算法版本）。

禁止没有分母的百分比。

---

# 8. WP-V06.6 — KnowledgePoint 学情

API建议：

`GET /api/v1/teacher/courses/{courseId}/analytics/knowledge-points?from=...&to=...`

每个 KnowledgePoint 至少返回：

- id/code/name；
- observedStudentCount；
- unknownStudentCount；
- meanMastery（仅 OBSERVED）；
- medianMastery（建议）；
- weakObservedStudentCount；
- attemptCount；
- correctCount；
- correctRate；
- masteryAlgorithmVersions。

注意：

- current mastery 为当前状态；
- answer correctRate 可按请求窗口；
- 两者时间语义不同，响应中必须明确，不得假装同一统计口径。

若实现“窗口末 mastery snapshot”成本过高，本阶段不造假；直接声明 mastery = current state。

---

# 9. WP-V06.7 — Student × KnowledgePoint Heatmap

API建议：

`GET /api/v1/teacher/courses/{courseId}/analytics/mastery-heatmap?page=0&size=50`

要求分页，禁止一次返回无限学生 × 全知识点大矩阵。

至少：

```text
students[]:
  studentId
  displayName
  items[]:
    knowledgePointId
    status UNKNOWN|OBSERVED
    masteryScore nullable
    attemptCount
    algorithmVersion nullable
```

默认 page size <= 50，最大建议 <= 100。

教师只能看到本课程 ACTIVE enrollment 学生。

# 10. WP-V06.8 — High-error Questions

API建议：

`GET /api/v1/teacher/courses/{courseId}/analytics/questions/errors?from=...&to=...&limit=20`

至少返回：

- questionId；
- ExerciseUnit；
- stemPreview（受控长度）；
- attempts；
- wrongCount；
- wrongRate；
- distinctStudents；
- associated KnowledgePoints。

排序建议：

1. minimum sample threshold 后 wrongRate desc；
2. wrongCount desc；
3. questionId稳定 tie-break。

必须避免“1个人做1次错了=100%，就排第一”的误导。

可预设 minimumAttempts，例如5；在 fixture/小班级可通过参数或明确 fallback 测试。

# 11. WP-V06.9 — Student Detail

API建议：

`GET /api/v1/teacher/courses/{courseId}/students/{studentId}/analytics`

必须先检查：

1. 当前教师有课程权限；
2. student 是该课程 ACTIVE enrollment。

返回可拆成多个API，但整体至少覆盖：

- student basic non-sensitive display info；
- current mastery list；
- weak observed points；
- recent answers（分页/limit）；
- current/recent mastery history；
- latest recommendation snapshot（若存在）；
- current Published graphVersionId（若存在）；
- activity summary。

不返回：

- password hash；
-其他课程记录；
- Research Student ID；
-无业务需要的个人敏感字段。

# 13. 查询实现原则

优先：

- Spring Data repository +明确SQL/JPQL；
- projection DTO；
- MySQL聚合；
- 分页。

避免：

- N+1；
- 把整个answer_record加载到Java后再统计；
- 每个KnowledgePoint循环发一次SQL；
- 每个student循环发一次SQL。

对关键 analytics query 做至少一种：

- repository integration test；
- SQL EXPLAIN记录；
- 可控fixture性能测量。

# 16. 数据隐私/审计

V0.6日志和前端：

- 不打印JWT；
- 不打印password hash；
- 不在URL/query暴露不必要的个人数据；
- student analytics必须通过 course enrollment 校验；
- API错误不返回数据库内部堆栈/SQL。

可记录：

- requester user ID；
- course ID；
- operation；
- window；
- status。

本阶段不强制新增完整 audit_log 表，除非实现已有统一审计机制。
