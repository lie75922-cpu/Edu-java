# V0.2 工程范围与验收标准

## 1. 阶段目标

V0.2 不做AI效果集成，目标是建立稳定的平台业务数据模型和最小学习闭环：

```text
登录
→ 课程
→ 知识主题
→ ExerciseUnit
→ Question
→ 提交答案
→ AnswerRecord
→ 基础学习记录
```

MODEL-0与V0.2可并行，但V0.2不得依赖某个具体认知诊断模型才能运行。

## 2. 冻结领域边界

依据ADR-0002：

```text
Course
 └─ KnowledgeArea
     └─ KnowledgePoint (Topic来源的第一版可解释知识层)
         └─ ExerciseUnit
             └─ Question
```

注意：

- `ExerciseUnit` ≠ `Question`；
- `ExerciseUnit` ≠ `KnowledgePoint`；
- Junyi匿名学生不得导入平台User；
- model concept不进入业务主键设计。

## 4. Research Data Import边界

V0.2允许提供一个**管理员/离线seed importer**：

可以导入：

- Area；
- Topic→KnowledgePoint；
- 非冲突Exercise→ExerciseUnit；
- Exercise→Topic映射。

禁止自动导入：

- Junyi user；
- Junyi ProblemLog到正式answer_record；
- raw prerequisite到PUBLISHED Neo4j graph；
- relationship annotation作为生产关系。

重复external ID只进入import conflict report。

## 5. API范围

### Auth

- POST `/api/v1/auth/register`
- POST `/api/v1/auth/login`
- GET `/api/v1/users/me`

### Course

- GET `/api/v1/courses`
- GET `/api/v1/courses/{id}`
- GET `/api/v1/courses/{id}/knowledge-points`

### Exercise / Question

- GET `/api/v1/exercise-units`
- GET `/api/v1/exercise-units/{id}`
- GET `/api/v1/exercise-units/{id}/questions/next`
- POST `/api/v1/questions/{id}/answers`

### Admin最小接口

- Course CRUD
- KnowledgePoint CRUD
- ExerciseUnit CRUD
- Question CRUD
- Seed import dry-run / apply / conflict report

## 6. 事务要求

答题提交必须：

```text
BEGIN
幂等检查
判题
保存AnswerRecord
写Outbox事件（预留MASTERY_UPDATE_REQUEST）
COMMIT
```

V0.2可以暂不消费Mastery事件，但不能把未来异步更新设计成不可靠的进程内`@Async`唯一机制。

## 7. 前端范围

学生端最小页面：

- 登录/注册；
- 课程列表；
- 课程知识主题；
- ExerciseUnit列表；
- Question作答页；
- 作答结果/解析；
- 基础学习历史。

管理端最小页面：

- Course；
- KnowledgePoint；
- ExerciseUnit；
- Question；
- Seed Import结果与冲突。

V0.2不做：

- Mastery雷达图；
- 推荐；
- 学习路径；
- 教师热力图；
- LLM/Agent。

## 8. 测试要求

必须覆盖：

- Auth权限；
- Course CRUD；
- Exercise/Knowledge映射；
- Question判题；
- 重复clientRequestId；
- 不存在Question；
- 禁用Question；
- 无权限课程；
- 事务回滚；
- Outbox生成；
- Junyi seed重复ID进入conflict而非自动merge；
- Junyi user不会被导入sys_user。
